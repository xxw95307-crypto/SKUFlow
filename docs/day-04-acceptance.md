# Day 4 验收：商品事实抽取与证据追踪

## 当日交付

- 百炼接入：服务端通过 OpenAI 兼容的 `/chat/completions` 接口调用 `qwen3.8-max`。
- 事实抽取 Agent：将 Day 3 的 PDF 页、Excel 工作表范围和文本行块编译为带编号的证据上下文。
- 结构化结果：模型只返回 JSON；应用在入库前再次校验字段、值、单位、置信度和证据引用。
- 证据追踪：每个非空模型事实至少绑定一个真实证据，界面展示文件名以及页码、单元格范围或行号。
- 冲突检测：同一字段出现不同候选值时不自动裁决，全部写入冲突账本并将事实标记为 `CONFLICT`。
- 缺失检测：16 个核心商品字段若没有现有值或可靠证据，明确写入 `MISSING`，不使用常识补齐。
- 人工值保护：已由用户确认的值不会被模型静默覆盖；模型提出不同值时转为待确认冲突。
- Agent 审计：D1 记录模型、Prompt 版本、输入哈希、运行状态、结构化输出、Token 用量和安全错误摘要。
- 工作流推进：抽取成功后进入 `FACTS_EXTRACTED`；存在冲突或缺失时进一步进入 `NEEDS_CONFIRMATION`。

## 可操作验收

1. 创建任务并上传包含商品参数的 PDF、XLSX/CSV 或 TXT。
2. 点击“开始解析并查看结果”，确认任务进入“资料已解析”。
3. 在商品护照页面点击“启动事实抽取”。
4. 等待百炼返回后，检查事实表中的值、来源、置信度和状态。
5. 对同一字段在两个资料中提供不同值，确认该字段显示“存在冲突”，且冲突账本保留两个候选值及来源。
6. 检查没有证据的核心字段显示“待补充”，而不是由模型猜测填充。
7. 刷新页面，确认事实、证据、冲突和最近一次 Agent 运行仍可恢复。

## API

- `GET /api/tasks/:taskId/extract-facts`：读取百炼配置状态、模型名称和最近一次 Agent 运行。
- `POST /api/tasks/:taskId/extract-facts`：调用百炼、验证结构化输出并原子化写入事实、证据、冲突与运行记录。

## 核心字段

商品名称、品牌、型号、候选类目、商品描述、主要材质、颜色、容量、额定功率、额定电压、商品净重、商品尺寸、电池容量、电池能量、包装清单和认证信息。

## 安全与能力边界

- `BAILIAN_API_KEY` 仅作为服务端托管环境的加密变量存在；仓库只有空值示例。
- 浏览器接口只返回“是否已配置”，不会返回密钥内容。
- API 错误只保留 HTTP 状态和 Request ID，不记录响应正文，避免供应商响应意外进入日志。
- 当前 Token Plan 专属接口支持文本推理，因此 PDF/Excel/TXT 的已解析文本可进入 Agent；图片内容块只计数并标记为待视觉处理。
- 图片商品参数要在后续接入支持视觉理解的百炼多模态模型及相应 API 凭据，不能复用本阶段的文本能力假装识图。

## Day 4 / Day 5 分界

Day 4 产出可信的规范化商品事实与证据链；Day 5 将定义通用 Platform Adapter SDK，让各平台适配器读取已确认的 Product Passport，而不直接读取原始文件或调用抽取模型。
