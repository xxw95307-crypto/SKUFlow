# Day 3 验收：多格式文件统一解析

## 当日交付

- 图片解析：识别 PNG、JPEG、WebP，提取格式、像素尺寸、哈希和视觉内容块。
- PDF 解析：逐页提取文本并保留页码定位；扫描型 PDF 返回可继续进入视觉识别的部分成功结果。
- Excel 解析：读取 XLSX、XLS、CSV 的工作表、范围、表头和单元格行。
- 文本解析：支持 UTF-8、UTF-16 文本，按行号分块。
- 统一结果：所有解析器输出 `UnifiedParseResult v1.0`，包含文本、内容块、定位、元数据、警告、错误与哈希。
- 持久化：解析结果进入 D1，源文件仍保存在 R2；刷新页面后结果可恢复。
- 工作流：任务新增 `FILES_PARSED` 状态，明确区分“源文件已解析”和 Day 4 的“事实已提取”。

## 可操作验收

1. 新建任务，上传图片、PDF、Excel/CSV 或 TXT。
2. 点击“开始解析并查看结果”。
3. 商品档案页面展示每个文件的解析器、完成状态、内容预览、字符数和内容块数。
4. 点击“下载统一 JSON”，获得可供后续 Agent 消费的完整统一结果。
5. 点击“重新解析”，系统重新读取 R2 源文件并覆盖该文件的最新解析结果。

## API

- `POST /api/tasks/:taskId/parse`：解析尚未完成的源文件。
- `POST /api/tasks/:taskId/parse`，请求体 `{ "force": true }`：强制重新解析。
- `GET /api/tasks/:taskId/parse`：读取任务的统一解析结果与汇总。

## 资源边界

- 单份统一结果最多保留 120,000 个文本字符。
- PDF 最多保留 200 个非空页面块。
- 工作簿最多保留 20 个工作表，每表 200 行 × 50 列预览。
- 加密 PDF、损坏文件与 Day 3 未覆盖的格式会形成失败结果，不会阻断同一任务中其他文件。

## Day 3 / Day 4 分界

Day 3 负责把异构文件变成有定位的统一内容块；Day 4 才会从这些块中抽取商品事实、计算置信度、建立证据引用并检测冲突。
