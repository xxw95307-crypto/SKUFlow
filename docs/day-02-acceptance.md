# Day 2 验收：Product Passport 与任务状态机

## 当日交付

- 商品结构：任务下维护带版本号的 `ProductPassport`，区分根级事实与 SKU 变体事实。
- 证据结构：每条证据记录来源类型、源文件、定位信息、摘录与内容哈希；事实通过关联表引用证据。
- 冲突结构：同一事实可保留多个候选值、各自证据与最终人工/Agent 裁决。
- 平台草稿结构：按“平台 × 市场”建立独立草稿，分别维护类目、Schema 版本、载荷、校验问题和生命周期状态。
- 任务状态机：每个状态标注责任方、所处阶段、是否需要人工操作及是否为终态。

## 可操作验收

1. 新建任务并上传文件，任务与源文件持久化的同时自动生成 Product Passport v1。
2. 打开“商品档案”，能读取真实的商品事实、证据数、冲突数和平台草稿数。
3. 填写“品牌”和“候选类目”后保存，护照版本递增，字段状态变为“已确认”，每次修改新增一条 `USER_INPUT` 证据。
4. 刷新页面后，最新任务和修改后的商品护照仍能恢复。
5. 旧 Day 1 任务第一次读取护照时会自动补建 v1，不需要删除历史任务。

## API

- `GET /api/tasks/:taskId/passport`：读取最新商品护照。
- `PATCH /api/tasks/:taskId/passport`：人工补充或更新事实，并写入证据与新版本号。

## Day 2 边界

Day 2 完成的是 Agent 可消费、可追溯、可扩展的数据底座。图片、PDF、Excel 和文本的自动解析属于 Day 3；平台字段编译与正式 Adapter 属于 Day 5–6。
